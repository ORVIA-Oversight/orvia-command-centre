# ORVIA COMMAND — Parallel Build Master

**Version:** 30 Sep 2026 — Live Build  
**Owner:** IRIS / Command Suite  
**Scope:** Universal Context Intake + Agent Capability Build

## Non-negotiable architecture

User → IRIS → Specialist Agents / Skills / Model Gateway → HIVE → VITA / VERA → Human Approval where required → Action

- IRIS remains the only user-facing interface.
- Do not create another orchestration dashboard or top-level product.
- Users never choose providers, model names, routing codes or APIs.
- Consequential safeguarding, clinical, legal, employment, financial or culpability decisions remain human-authorised.
- Universal intake is a core IRIS capability, not an optional add-on.
- Experience target: **Open Command → talk to IRIS → attach anything → ask once → IRIS handles the rest.**

## Universal context intake

Supported target inputs:
- PDF, DOCX, XLSX/CSV, PowerPoint and text
- images and screenshots
- audio and video
- safe ZIP evidence packages
- URLs
- ORVIA SharePoint links
- existing HIVE/library items
- email/message references
- later: other connected cloud files

IRIS must automatically:
1. identify the input;
2. preserve the original and provenance;
3. route it to the correct ingestion/extraction capability;
4. register it with HIVE;
5. make it available to the current request;
6. permit later authorised retrieval;
7. distinguish source material from verified evidence;
8. never overwrite the original;
9. enforce human authority for consequential decisions.

## Delivery rules

- Reuse current Command database, auth, HIVE/assurance structures and agent gateway first.
- Do not duplicate storage simply because a new agent prefers a different schema.
- Mobile-first.
- Plain ORVIA language, not backend jargon.
- Provider identities are implementation details and are not surfaced in normal IRIS conversations.
- Completion requires acceptance tests, not just documentation.
